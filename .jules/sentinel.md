## 2024-06-15 - [Telegram HTML Injection via parse_mode]
**Vulnerability:** The `api/save-lead.js` endpoint explicitly configured the Telegram `sendMessage` API to use `parse_mode: 'HTML'` but directly interpolated unescaped user inputs (`name`, `phone`, `experience`, `pattern`) into the HTML string. An attacker could submit a payload containing special HTML characters (like `<`, `>`, `&`) which would break the Telegram markup and cause the Telegram API to return a 400 Bad Request, effectively resulting in a Denial of Service for lead notifications, or potentially allowing them to format the message maliciously if the characters were crafted to close and open specific tags.
**Learning:** Even internal notification systems like Telegram bots are vulnerable to injection attacks if they support HTML/Markdown parsing and handle unsanitized user input. The impact isn't just XSS (as Telegram sanitizes execution), but robust delivery failure (DoS) because the API strictly validates the HTML structure.
**Prevention:** Always sanitize/escape user inputs before interpolating them into strings that will be parsed as HTML or Markdown by third-party APIs. Use a robust `escapeHTML` function or switch to plain text mode if rich formatting is unnecessary.
