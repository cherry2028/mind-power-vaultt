## 2025-06-05 - Hardcoded Secrets & Client-Side Auth Bypass
**Vulnerability:** The application contained a hardcoded admin password (`VITE_ADMIN_PASSWORD` / `"mpv@kprasad2028"`) in `src/App.jsx` and an internal API key (`VITE_INTERNAL_API_KEY`) used for a custom `x-internal-key` header in API requests. Additionally, the admin login logic was entirely client-side, making it trivial for an attacker to bypass authentication and gain access to the admin panel by reading the bundled JavaScript.
**Learning:** Prefixing environment variables with `VITE_` automatically exposes them to the client-side bundle. This means any sensitive keys or passwords will be visible to any user who inspects the application's source code. The reliance on `x-internal-key` for public-facing API endpoints is also flawed, as Vercel's same-origin protection should be sufficient. Client-side authentication checks offer zero real security.
**Prevention:** Never prefix sensitive backend secrets with `VITE_`. All authentication logic must be handled server-side via established endpoints (e.g., `/api/validate-code`) that verify the credentials and return a secure JWT. Public-facing API endpoints that are consumed by the frontend should rely on Vercel's same-origin protection rather than exposing internal keys to the client.
