## 2024-05-19 - Unescaped User Input in Telegram HTML Parsing
**Vulnerability:** The `/api/save-lead.js` endpoint constructed a Telegram message string using unescaped user input and sent it with `parse_mode: 'HTML'`. If a user submitted text with characters like `<` or `&`, it could cause a Telegram API `400 Bad Request: can't parse entities` error, dropping the lead completely and exposing the app to HTML injection inside Telegram.
**Learning:** Telegram's HTML parsing mode is strict. Unsanitized user inputs break the parsing, turning an XSS-style input into a Denial of Service (lost leads) for internal notifications. This is a unique failure mode for integrations where "HTML Injection" causes message delivery failure rather than client-side execution.
**Prevention:** Always sanitize user inputs using a function like `escapeHTML` (replacing `&`, `<`, `>`, `"`, `'`) before embedding them in strings destined for Telegram (or other strict markdown/HTML parsing APIs) when a parse mode is enabled. Alternatively, omit `parse_mode` for pure text payloads.
