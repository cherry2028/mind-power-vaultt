## 2025-02-28 - SSRF / Path Traversal via Unvalidated URL Path Parameters
**Vulnerability:** In serverless functions that interact with third-party APIs (like `api/verify-payment.js` with Cashfree), user-supplied IDs (like `order_id`) were being directly interpolated into external API URLs (`https://api.cashfree.com/pg/orders/${order_id}`) without validation. This allows an attacker to supply a malicious payload like `../../` to perform SSRF or path traversal against the third-party API.
**Learning:** Even when interacting with external APIs, user input used in URL paths must be strictly validated. Relying on the third-party service to handle invalid inputs isn't sufficient as it might still expose the server to SSRF or path traversal attacks depending on how the requests are constructed and forwarded.
**Prevention:** Always validate user-provided parameters used in URL paths using a strict regex (e.g., `/^[a-zA-Z0-9_.-]+$/`) or a whitelist before constructing the URL for external requests.
